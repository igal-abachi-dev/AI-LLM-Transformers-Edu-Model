## M7 Muon laboratory

- `newton_schulz_reference` is an annotated FP32 teaching function over tiny 2-D matrices.
  Production construction cannot select it and calls first-party `torch.optim.Muon` only.
- Hidden 2-D projection matrices use Muon. Tied token embeddings, norms, scalars, and all remaining
  parameters use AdamW. Tests prove the partition is disjoint and complete.
- `CombinedOptimizer` exposes one scheduler/checkpoint surface while preserving the two first-party
  optimizer states and optimizer-specific LR scaling.
- The general comparison CLI uses identical initialization/data order/token budget, separate LR
  grids, and retained checkpoints for every arm. The bounded CPU smoke records four matched arms at
  [`reports/m7-muon-cpu-smoke.json`](../../reports/m7-muon-cpu-smoke.json). It makes no optimizer
  quality, VRAM, or scale claim.

## M8 assistant-only SFT and chat

- The checked-in Jinja template deterministically serializes optional system plus alternating
  user/assistant turns. Invalid roles/order and empty content fail clearly.
- Conversation JSONL requires source, revision, license, record ID, and canonical content hash.
  Token-level masks exclude BOS, role, system, user, newline, padding, and truncated context while
  training assistant content and its EOS boundary.
- Truncation removes only complete oldest user/assistant pairs. A single oversized remaining turn
  fails rather than being silently sliced. Packing preserves masks across fixed-length batches.
- `train/sft.py` reuses the raw trainer/checkpoint path, records base-weight and dataset hashes, and
  rejects resume lineage/configuration mismatches. Epoch-dependent batch ordering is deterministic,
  and exact resume restores and validates its seed, policy, epoch, cursor, and batch count. The
  strict tiny assistant-only overfit reaches below `0.02`; the persisted smoke reached `0.0005752459` at
  [`reports/m8-sft-cpu-smoke.json`](../../reports/m8-sft-cpu-smoke.json).
- The versioned CC0 prompt set and transparent substring/non-empty scorer support fixed-seed
  base-versus-SFT reporting without pretending the tiny suite measures broad assistant quality.
- The chat CLI uses the same template, preserves whole turns under context pressure, exposes finite
  sampling/device/precision/seed controls, and states its single-user educational scope. The concise
  checked-in default system prompt is capability-honest, can be overridden or disabled, and is
  included in the release hash manifest. A multi-turn contract test proves Jinja rendering, runtime
  encoding, and SFT serialization produce the same token sequence.

## Pre-M10 correctness and packaging audit

- Bounded local decode now exposes `window - 1` historical keys plus the current key. Full-forward
  versus token-by-token parity is regression-tested beyond two complete ring wraps with exact
  argmax agreement. This closes the confirmed local-cache off-by-one defect.
- Cached one-token local `auto` attention was already dispatched to SDPA, so the reported unbounded
  per-token Flex block-mask-cache growth was not present in the audited tree. Backend-selection and
  stable-cache-size tests remain in place.
- Exception-safe cache rollback remains enabled. Its copy/allocation traffic is explicitly retained
  as an MF-050 CUDA profiling item rather than optimized without measurements.
- All PyTorch extras are constrained to the locked V1 minor line `>=2.13.0,<2.14`.
- `scripts/build_source_archive.py` produced a verified 144-file audit archive including the GitHub
  Actions workflow and excluding bytecode, caches, artifacts, weights, corpora, and bundled
  research/reference material.
