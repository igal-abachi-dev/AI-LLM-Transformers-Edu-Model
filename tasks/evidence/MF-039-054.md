# MF-039–054 implementation evidence

Environment: Windows 11 Azure Dev Box, Python 3.12.1, PyTorch 2.13.0+cpu, no CUDA device. Date:
2026-08-18.

## M4 Modern

- Compact GQA is implemented for manual, SDPA, and FlexAttention paths. Only the manual teaching
  path repeats K/V; optimized paths use native GQA.
- Optional per-head QK-Norm runs before RoPE. Hybrid layers follow Local/Local/Local/Global, with
  cached exact-window Flex block masks. Global NoPE changes only global layers.
- FP32 outputs/gradients, cache prefill/token/chunks, exact argmax, window bounds, unwritten slots,
  truncation, dispatch, and parameter/cache reductions have focused tests.
- The slow Modern overfit reached `0.0002819` nats/token in the implementation run. The matched 50M
  CPU construction report records 53,361,152 Edu versus 47,857,920 Modern parameters and
  3,670,016 versus 917,504 allocated FP32 cache bytes at capacity 64. This is not a speed or quality
  comparison: [`reports/m4-50m-cpu-smoke.json`](../../reports/m4-50m-cpu-smoke.json).

## M5 performance implementation

- The canonical trainer includes AdamW grouping, update-indexed warmup/cosine, clipping, exact
  token-weighted accumulation, CPU validation, BF16 policy, activation checkpointing, optional
  path-labeled compile, periodic checkpoints, and exact shard-cursor resume.
- Immutable uint16 token/count shards are hash-verified, atomically published as separate `.npy`
  arrays, and memory-mapped with one cached shard per worker; SQLite exact/near dedup and evaluation
  exclusions retain aggregate signatures/counts rather than rejected text. The preparation CLI can
  stream the pinned FineWeb-Edu revision directly without a giant intermediate JSONL.
- Training order uses deterministic per-epoch shard and bounded within-shard row permutations.
  Seed, shuffle policy, epoch, shard cursor, and row cursor are checkpointed and mismatch-validated.
- Deterministic interruption/resume produces bit-exact weights in the fixture test. CPU BF16 full
  versus cached Modern inference remains finite and preserves every argmax; the fixed numerical
  tolerance remains a CUDA gate because CPU prefill/decode kernels use different reduction shapes.
- Generation uses selective last-position logits and preallocated output storage. The profiling CLI
  records cache dtype/bytes, prefill/decode latency, compile state, determinism, and CUDA VRAM fields.
- Optional local ring caches retain only the configured window while global layers retain full
  history. FP32 tests prove wrap/chunk/reset/failure-rollback parity and exact argmax; single-token
  local decode uses SDPA and does not grow the Flex block-mask cache per absolute position.
- A 50M CPU inference record completed at
  [`reports/m5-50m-cpu-inference-smoke.json`](../../reports/m5-50m-cpu-inference-smoke.json).
  Its timings are not GPU recommendations. CUDA BF16, fused-backend, compile, VRAM,
  activation-checkpoint, and 8K+ hybrid measurements keep MF-046/MF-049/MF-050 open until the home
  RTX gate.

## M6 code/FIM

- Code admission enforces permissive licenses/provenance and filters secrets, credentials, the
  documented PII policy, generated/vendor/minified/malformed content, duplicates, and evaluation
  overlap with versioned aggregate reasons.
- PSM FIM is deterministic, reconstructable, versioned, defaults to 15%, preserves provenance and
  stable split identity, and uses the frozen tokenizer tokens.
- A bounded one-update 50M baseline/FIM pair consumed exactly 15 target tokens per arm from identical
  initialization and retained resumable checkpoints plus input-manifest hashes:
  [`reports/m6-50m-cpu-smoke.json`](../../reports/m6-50m-cpu-smoke.json). Resumable local
  checkpoints live under the ignored `artifacts/m6-50m-cpu-smoke/` directory.
- The versioned reference-fixture scorer produced exact/syntax/compile/functional rates of 1.0 and a
  clean exact/near-contamination report at
  [`reports/m6-code-scorer-smoke.json`](../../reports/m6-code-scorer-smoke.json). Reference answers
  test the scorer; they are not model predictions.
